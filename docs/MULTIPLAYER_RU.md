# Мультиплеер — настройка сервера и подключение

<p align="right"><a href="./MULTIPLAYER.md">🇺🇸 English</a></p>

## Обзор

OpenOL поддерживает два режима сервера:

| Режим | Описание |
|-------|----------|
| **Встроенный relay** | Relay запускается внутри `OLGame.exe` — отдельный процесс не нужен. Хост создаёт игру из меню. |
| **Отдельный relay** | `OpenOL_Relay` запускается как отдельный процесс на любой машине с доступным IP. |

Весь трафик шифруется. У всех должна быть одна версия игры и relay: старые версии подключиться не смогут.

## Как получить исходники relay

Relay — это репозиторий [OpenOL-Relay](https://github.com/ShyKiss/OpenOL-Relay), подключённый к OpenOL как git-сабмодуль в `Development/Src/Multiplayer/server`. Он нужен и для `OLGame.exe`: встроенный relay (`openol_relay.lib`, пункт 11 в `build_wine.sh`) компилируется из того же кода.

```sh
git clone --recursive https://github.com/ShyKiss/OpenOL.git

# Если репозиторий уже склонирован без него или вы получили новую версию:
git submodule update --init
```

Чтобы только поднять сервер (например, на VPS), клонируйте один relay. Исходники игры ему не нужны:

```sh
git clone https://github.com/ShyKiss/OpenOL-Relay.git
```

---

## Режим 1 — Встроенный relay (хостинг из игры)

1. Запустите игру
2. Откройте **Мультиплеер** -> **Запустить сервер**
3. Relay запускается в фоновом потоке; клиенты подключаются через **Steam P2P** — открытые порты и публичный IP не нужны
4. Код комнаты: `DEFAULT`

Relay останавливается автоматически при выходе хоста.

---

## Режим 2 — Отдельный relay

Запустите `OpenOL_Relay` (TUI) или `OpenOL_Relay_GUI` (GUI) на сервере или любой машине, доступной клиентам.

Сборка на Linux из папки `src` репозитория relay (внутри OpenOL это `Development/Src/Multiplayer/server/src`):

```sh
./build.sh         # TUI: build/OpenOL_Relay
./build.sh --gui   # ещё и GUI: build/OpenOL_Relay_GUI
```

На Windows запустите `build_win.bat` из той же папки. Запуск relay в контейнере описан в [HOSTING.md](https://github.com/ShyKiss/OpenOL-Relay/blob/main/docs/HOSTING.md).

Параметры командной строки: `--port <порт>`, `--ip <адрес>`, `--name <имя>`.

### Конфигурация

Все настройки хранятся в `relay.db` (JSON), создаётся автоматически рядом с бинарником при первом запуске:

```json
{
  "config": {
    "name":  "OLServer",
    "ip":    "0.0.0.0",
    "port":  "7777"
  },
  "rooms": [
    {
      "code":     "PUBLIC",
      "password": "",
      "trusted":  [],
      "bans":     []
    }
  ],
  "bans": []
}
```

Файл перезаписывается при изменении настроек через команды/GUI и при завершении сервера. Пароли комнат хранятся только как Argon2-хэши, а открытые пароли из старого файла переводятся при запуске. Список `trusted` больше не используется.

### Ключ сервера

При первом запуске relay создаёт `relay.db.key` рядом с `relay.db` и пишет в лог `Server key: <hex>`. Клиенты запоминают этот ключ и не подключаются, если он изменился.

- Храните этот файл и делайте его резервную копию. В контейнере держите `relay.db` и `relay.db.key` на томе.
- Если ключ потерян, игрокам нужно удалить строку этого сервера из `OLMultiplayer.ini`, а пароли комнат задать заново через `setpw`.

### Команды

Доступны в строке ввода TUI или на вкладке **Log** в GUI:

| Команда | Описание |
|---------|----------|
| `list` | Список игроков по комнатам |
| `rooms` | Список активных комнат |
| `kick <id>` | Кикнуть игрока |
| `ban <id> [reason]` | Глобальный бан по IP |
| `ban room <code> <id> [reason]` | Бан в конкретной комнате |
| `unban <ip>` | Снять глобальный бан |
| `unban room <code> <ip>` | Снять бан в комнате |
| `bans` | Список всех банов |
| `stats` | Ключ сервера, трафик, отказы во входе и соединение каждого игрока |
| `room create <code> [password]` | Создать комнату |
| `setpw <code> <password>` | Сменить пароль комнаты |
| `log on\|off` | Включить или выключить лог пакетов |
| `quit` | Остановить сервер |

Баны работают по IP. У всех гостей, подключённых через Steam P2P, адрес `127.0.0.1`, поэтому бан одного из них забанит всех.

### Симулятор ИИ врагов (необязательно, экспериментально)

По умолчанию ИИ врагов работает у одного из игроков. Вместо этого его можно запустить в отдельном процессе игры без окна. Для этого файлы игры должны быть на одной машине с relay, а скрипт ниже рассчитан на Linux (Wine + Xvfb).

Запуск relay вместе с симулятором:

```sh
OUTLAST_DIR=/path/to/Outlast Development/Src/Targets/run_simnode.sh --relay [port] [room]
```

Порт по умолчанию — `7777`, комната — `PUBLIC`. Задайте `WINEPREFIX`, если ваш префикс не `~/OL1Editor`.

Чтобы использовать relay, уже работающий на этой машине, запустите его с переменной `OPENOL_SIM_SECRET`, а затем запустите скрипт с тем же значением и без `--relay`. Relay без этой переменной не пускает симуляторы.

Запускайте симулятор до того, как игроки войдут в игру. В уже идущем мире он получит врагов только после того, как их текущий владелец выйдет или умрёт.

## Подключение клиентов

### Прямой UDP

1. В игре откройте **Мультиплеер** -> **Подключиться**
2. Введите IP и порт сервера (например, `123.45.67.89:7777`)
3. Введите код комнаты:
   - `DEFAULT` — встроенный relay (хост из игры)
   - `PUBLIC` — комната по умолчанию на отдельном relay
   - Любой другой код, созданный через `room create`
4. Введите пароль комнаты, если требуется

Если сервер отказал в подключении, причина (например, неверный пароль) появится в уведомлении в игре.

#### Если ключ сервера изменился

При первом подключении игра сохраняет ключ сервера в `OLGame/Config/OLMultiplayer.ini`:

```ini
[OLGame.OLKnownServers]
123.45.67.89:7777=<hex>
```

Если позже ключ будет другим, игра не подключится: возможно, кто-то выдаёт себя за сервер. Если администратор сервера подтвердил, что ключ действительно сменился, удалите эту строку и подключитесь снова.

Строка сверяется с адресом именно в том виде, в каком вы его вводите. Чтобы защитить и первое подключение, узнайте ключ у администратора и добавьте строку сами до подключения. Подключения к `127.0.0.1` не сохраняются. Для Steam P2P строка называется `steam:<Steam ID хоста>`.

### Steam P2P (встроенный relay)

1. Хост открывает **Мультиплеер** -> **Запустить сервер**
2. Хост приглашает друзей через Steam overlay (Shift+Tab -> Друзья -> Пригласить в игру)
3. Клиент принимает приглашение — игра запускается и подключается автоматически

Открытые порты и IP-адрес не нужны ни одной из сторон. Оба игрока должны быть в Steam.

### Porthole (отдельный relay без проброса портов)

[Porthole](https://porthole.sestudio.org) туннелирует конкретные UDP-порты через Steam — без VPN, виртуального адаптера и публичного IP.

1. Хост запускает отдельный relay локально (`OpenOL_Relay`, порт `7777`)
2. Хост открывает Porthole, создаёт лобби и открывает **UDP порт 7777**
3. Хост отправляет код приглашения всем игрокам
4. Каждый игрок открывает Porthole, вводит код и подтверждает порт
5. Все подключаются в игре к **`127.0.0.1:7777`**, код комнаты `PUBLIC`

Весь трафик туннелируется через Steam только между приглашёнными игроками.
